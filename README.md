# 黒板 · KOKUBAN

**書く。ひらめく。聴く。**

PC・スマートフォン・タブレットで利用できる、黒板とチョークのノートアプリです。ブラウザの表示領域いっぱいを筆記面として使い、必要な道具だけを重ねて開きます。

公開先: [黒板を開く](https://uni-tadayasu.github.io/note/)

## 最初の画面

初回は、サンプルの文章やイラストがない空の黒板から始まります。通常の筆記画面には、小さな専用の「道具」ボタンを配置します。ノート一覧・筆記道具・読み上げ・設定は、そのボタンから必要なときに開くオーバーレイです。閉じると、黒板いっぱいに書く画面へ戻ります。

黒板をタップ・ダブルタップ・ダブルクリック・右クリックしても、操作メニューは開きません。道具を変える場合は専用ボタンを使ってください。黒板上ではブラウザ標準の右クリックメニュー、長押しの選択表示、タッチによる拡大やジェスチャーを抑制し、筆記に集中できるようにしています。テキストの入力・編集は、道具からテキスト機能を選んで行います。

以前のバージョンで作成したノート・筆跡・文章・辞書は保持します。新しい画面への切り替えで、保存済みのユーザーデータを削除しません。

## 主な機能

- ペン・マウス・指での手書き。筆圧、Pointer Events、まとめられた入力点、曲線補間、ポインターキャプチャに対応。
- PC・スマートフォン・タブレットの表示領域に対応する全面の黒板。筆記面を押す操作からメニューを呼び出さず、専用ボタンから道具を開きます。
- チョーク、蛍光チョーク、色・太さ、消しゴム、直線、四角形、楕円、範囲選択、手書きのUndo/Redo。
- 配置するテキストの書体・サイズ・色・読み方の指定。既存の文字はテキストツールで編集できます。
- 日本語・英語の手書き文字認識。端末内のWeb Workerで実行し、文字の画像を外部サービスへ送信しません。結果を確認・修正してから挿入します。
- 日本語の読み上げ、実在する端末音声の選択、速度・音量・高さ、試聴、一時停止・再開、全ページ連続、くり返し、読んでいる文章・ページへの追従。
- 読み方辞書と文章ごとの読み指定。`{漢字|よみ}` 形式の個別指定も可能です。
- ノートブック、複数ページ、検索、お気に入り、複製、ゴミ箱、復元。
- IndexedDBへの自動保存。保存失敗を明示し、未保存データを保持して再試行できます。
- 無地・ドット・方眼・横罫・コーネル罫、3色の黒板。道具を閉じた状態では黒板を表示領域いっぱいに使います。
- PNG画像、テキスト、全ページのPDF／印刷、全ノートJSONバックアップ、バックアップの追加読み込み。
- PWA、基本機能のオフライン利用、文字認識データを明示的にオフライン準備する機能。
- オリジナルアイコン、ファビコン、iOSホーム画面用アイコン、1200×630のOGP画像。

## 使い方

1. 初回は、そのまま空の黒板にペン・マウス・指で書き始められます。
2. 色や太さ、消しゴムなどを変えるときは、小さな「道具」ボタンを押します。選択後はオーバーレイを閉じて筆記を続けます。
3. ノートを増やす場合は、道具からノート一覧を開き、「新しいノート」でノート名・ノートブック・罫線を選びます。
4. 文字変換では、道具から範囲選択を選び、認識したい文字を囲んで「文字に変換」を押します。変換結果を確認・修正してから黒板に挿入します。元の手書きは残ります。
5. 読み上げる場合は、道具から「読み上げ」を開き、声・速度・音量を選んで再生します。人名・専門用語は読み方辞書に登録するか、テキスト編集画面で読みを指定します。
6. 「設定とバックアップ」で定期的にノートを書き出します。別の端末では、そのバックアップを読み込んでください。

### 精度と保存について

手書き入力を高頻度で取得して滑らかに描画しますが、端末の性能・ペン・ブラウザによって入力品質は変わります。手のひらの誤入力には「ペンのみで手書きする」を利用できます。

文字認識にはTesseract.jsと日本語・英語モデルを使用します。対応する端末・言語では標準の筆跡認識APIも利用します。OCRは整った横書きの文字を得意とし、崩し字・連続した筆記体・イラスト混在などでは誤認識があります。手書きの変換精度を100%保証するものではありません。

読み上げはブラウザのSpeechSynthesisと端末に用意された音声を使用します。誤読ゼロ、すべての固有名詞の正しい読み、一定のアクセント・イントネーションを保証するものではありません。読み方辞書・個別の読み・試聴で調整できます。オンライン音声を選ぶと音声提供者への通信が発生する場合があります。オフライン音声の提供状況は端末に依存します。

ノートはブラウザ内に保存します。サーバーのアカウント保存・端末間の自動同期はありません。ブラウザデータの削除、プライベートブラウズ終了、保存領域の削除により失われる可能性があるため、バックアップ機能を利用してください。サイトURL・ブラウザが変わると保存領域も変わります。

### ページ寸法と旧データ

ページごとに幅と高さを保存します。新しいページは作成時の表示領域に合わせた寸法を使い、データとして受け付ける幅・高さはそれぞれ64～16,384の論理座標です。画面の表示倍率や書き出し画像の解像度は、この保存座標とは別に調整します。

寸法を持たない旧バックアップは1400×900として読み込み、保存されている筆跡やテキストの座標を保持します。新しい画面への移行情報は `boardLayoutVersion` で管理し、移行のために既存ノートを削除する処理は行いません。

## 開発と公開

フレームワーク・APIキー不要の静的HTML/ES Modulesです。Node.js 20以上で次を実行します。

```sh
npm test
npm run build
```

`build` はバージョンとSHA-256を固定した文字認識データとフォントをダウンロードして検証します。ランタイムでCDNへ接続する必要はありません。`dist/vendor/ocr/` とYomogiフォントは生成物のためGit管理対象外です。OCRデータは約14MBで、認識時に必要なエンジンだけを読み込みます。

`dist/` をHTTPサーバーで配信してください。`file://` での直接起動はES Modules、IndexedDB、Service Workerの制約により対応しません。

### GitHub Pages

`.github/workflows/pages.yml` はmainへのpushでテスト・ビルド・公開を行います。Pull Requestではテストとビルドを行います。GitHubの Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定してください。ワークフロー内の初回有効化が権限上許可されない場合は、管理者によるこの設定が必要です。

独自ドメインに変更する場合は、`index.html` のcanonical・OGP URLと`robots.txt`・`sitemap.xml`も更新してください。ノートはサイトのオリジンごとに保存されるため、変更前にバックアップしてください。

## 構成

| ファイル | 内容 |
| --- | --- |
| `dist/app.js` | ノート管理・画面操作・書き出し・認識連携 |
| `dist/ink.js` | 筆記・消去・選択・Undo/Redo・認識用画像 |
| `dist/speech.js` | 読み方補正・文章分割・音声制御 |
| `dist/recognition.js` | 標準筆跡認識と端末内OCR |
| `dist/storage.js` | 保存・バックアップ形式検証 |
| `dist/sw.js` | オフラインキャッシュ |
| `dist/assets/` | ブランド画像・フォント・ライセンス |
| `scripts/` | データ準備・検証・ブランド画像再生成 |
| `tests/` | 筆記・読み上げ・保存の動作テスト |
